# Story 1.5: Internacionalização (es/pt/en) com seletor

Status: ready-for-dev

## Story

Como usuário,
Quero trocar o idioma da interface,
Para que eu use o app no meu idioma.

## Acceptance Criteria

1. **Dado** react-i18next + i18next configurados com catálogos `pt`, `es`, `en`,
   **Quando** seleciono outro idioma via seletor no header,
   **Então** a UI re-renderiza imediatamente (sem reload de página) e a escolha persiste em `localStorage`.

2. **Dado** a aplicação abrindo pela primeira vez,
   **Então** a detecção de idioma segue: `localStorage` → idioma do navegador → default `pt-BR`.

3. **Dado** datas e números no layout,
   **Quando** o idioma muda,
   **Então** formatos de data e número respeitam o locale ativo (ex.: `Intl.DateTimeFormat`, `Intl.NumberFormat`
   ou via i18next `formatDate`/`formatNumber`).

4. **Dado** uma chave de tradução ausente (ex.: conteúdo es/en ainda não traduzido),
   **Quando** o idioma ativo é `es` ou `en`,
   **Então** exibe o valor do fallback `pt` — nunca a chave crua (ex.: `nav.home`) nem tela quebrada.

5. **Dado** suporte a pseudo-localização (dev-only),
   **Quando** ativado via `VITE_PSEUDO_LOCALE=true`,
   **Então** strings são padded (ex.: `[[[Início]]]`) para testar overflow de layout sem conteúdo final.

6. **Dado** as strings do shell (header, sidebar, labels de navegação),
   **Então** todas estão externalizadas nos 3 catálogos — zero hardcode.

## Dev Notes

### Estrutura de catálogos

Usar `defaultNS: 'common'` para strings globais. Features podem ter namespaces próprios:
- `common` — shell, nav, erros globais
- `home` — strings da Home
- `products` — catálogo, detalhe
- `discovery` — fluxo, cockpit
- etc. (a definir por feature)

Lazy loading de namespaces por rota (evitar carregar tudo upfront) — considerar `i18next-http-backend`
se os catálogos ficarem grandes.

### Chaves es/en como placeholder

Conforme Open Q6 (dono de conteúdo não definido), es/en entram com o valor PT até serem traduzidos.
Comentar no catálogo: `// TODO: traduzir para ES/EN`.

### Pseudo-localização

Útil para detectar:
- Strings hardcoded (não se expandem)
- Overflow de layout com textos longos
- Elementos sem tradução

### react-i18next hook padrão

```tsx
import { useTranslation } from 'react-i18next'

const { t, i18n } = useTranslation('common')
```
